# RAG + Ontology Layer

This folder holds the local Retrieval-Augmented Generation (RAG) and ontology
resources that ground the resident summary generator in the ACGME Internal
Medicine Milestones.

**Everything here stays local on this machine.** No data is sent to the cloud or
to any third-party service. The only network calls are to the local Ollama server
(`http://localhost:11434` by default) or, with the NVIDIA Nemotron engine, to the
two Nemotron containers on this machine (ports 8001 and 8002), for embeddings and
reranking.

## Folders

- **`documents/`** — Reference material in Markdown form. Holds the two ACGME
  reference files (`acgme_im_milestones.md` and `acgme_im_supplemental_guide.md`)
  the generator retrieves context from. You place these here yourself.

- **`ontology/`** — The ACGME ontology in JSON form (`acgme_ontology.json`).
  Defines the six competency domains and the 21 sub-competencies (id, name,
  domain, plain-language evaluator keywords, and related ids). The keywords drive
  comment routing; review/tune them as needed.

- **`chroma_db/`** — The searchable vector index, generated by `build_index.py`,
  with one collection per retrieval engine (below). This is a build artifact and
  is git-ignored — rebuild it anytime from the Markdown files.

## Two retrieval engines

Keyword routing, the report skeleton, generation and quote validation are the
same whichever engine is in use. The engines differ only in how a comment that
matches **no** ontology keyword finds its sub-competency:

| | Standard (Ollama) | NVIDIA Nemotron |
|---|---|---|
| Embedding model | `qwen3-embedding:0.6b` via Ollama (`AUC_EMBED_MODEL`) | `nvidia/nemotron-3-embed-1b` in a local container (`AUC_NIM_EMBED_MODEL`) |
| Choosing the sub-competency | the nearest index entry | the embedder shortlists 10 entries (`AUC_RERANK_CANDIDATES`); the `llama-nemotron-rerank-vl-1b-v2` reranker, which reads the comment and each entry together, picks one |
| Index collection | `acgme_guidelines` | `acgme_guidelines_nemotron` |
| Runs on | anything that runs Ollama | a DGX Spark, or any machine with a capable NVIDIA GPU and Docker |

**Which one is used is chosen in Settings → Retrieval engine**, for the whole app.
With no choice made, a DGX Spark (detected by its GB10 GPU) uses NVIDIA Nemotron
and every other machine uses Standard. Settings only lets you switch to an engine
this machine can run right now *and* whose index is built, and the server checks
that again on the switch itself.

The engine never changes on its own. If the chosen one stops running — a
container down, Ollama stopped — summaries fail with a message saying so rather
than quietly using the other, and Settings offers the switch.

Each engine's collection is stamped with the embedding model that built it and
checked against it, exactly as the single index always was: vectors from one
embedder searched with another's return confident nonsense and no error. The
routing each summary used is recorded in `auc/data/logs/summary_validation.log`
(`engine=` on every line).

The Nemotron containers are started by `bash auc/start-nemotron.sh`, which
`setup.sh` runs on a Spark. They are defined in
[`../nim/docker-compose.yml`](../nim/docker-compose.yml), bound to this machine
only, and restart on their own after a reboot.

## Scripts

- **`build_index.py`** — Splits each Markdown file into one chunk per
  sub-competency (h3 headings), tags each chunk with the canonical id/name/domain
  from `ontology/acgme_ontology.json`, embeds it with the engine's embedding
  model, stamps that model name into the collection's metadata, and stores
  everything in a ChromaDB `PersistentClient` at `chroma_db/`. With no
  arguments it builds the collection for **every engine this machine can run**
  and says why it skipped any other; `--engine ollama` or `--engine nemotron`
  builds one. Idempotent — it deletes and recreates the collection on every run.
  Expect 42 chunks per engine (21 sub-competencies × 2 source files).

- **`test_query.py`** — Embeds a query string with an engine's model and prints
  the top 3 matching chunks (id, name, domain, source, distance). With
  `--engine nemotron` it also prints the reranked order, which is the order the
  app routes by. Without `--engine` it uses the engine the app is set to. Handy
  for sanity checks.

## How it grounds the summary generator

Retrieval lives in [`../backend/rag_retrieval.py`](../backend/rag_retrieval.py);
which engine it uses is decided in
[`../backend/retrieval_engine.py`](../backend/retrieval_engine.py); generation
lives in [`../backend/summary_builder.py`](../backend/summary_builder.py). The
current summary endpoint is `POST /api/residents/{id}/summary-stream`, which
streams Server-Sent Events — one event per sub-competency as it completes, then a
`done` event.

The key design rule is that **Python owns the report and the model only fills in
slots**:

1. Gathers the resident's evidence (committee notes + MedHub comments).
2. Routes each comment to sub-competencies by ontology keyword match; any comment
   that matches no keyword falls back to a semantic search of the index — nearest
   entry with Standard, embed-then-rerank with NVIDIA Nemotron — so nothing is
   dropped. *(`route_comments`.)*
3. Builds the report skeleton from `ontology/acgme_ontology.json` — always all
   **21** sub-competencies, ordered by domain. The model never sees this list and
   therefore cannot invent a sub-competency that isn't in the ontology.
4. For each sub-competency **that has routed evidence**, fetches both of its chunks
   (milestone level descriptors + supplemental-guide examples) and makes **one small
   model call** containing only that sub-competency's descriptor and only its own
   comments. The model returns JSON: a suggested level (1–5), a 2–3 sentence
   narrative in its own words, and exact quotes. The prompt forbids reusing
   descriptor language — the descriptor is reference material for forming a
   judgment, not source text.
5. Sub-competencies with **no** routed evidence are filled in by Python as "No
   evidence this cycle". No model call is made for them.
6. **Validation.** Every returned quote must appear verbatim (case-insensitive) in
   the comments actually routed to that sub-competency; quotes that don't are
   dropped. If no quotes survive, the narrative and level are discarded and the
   section is marked "insufficient evidence" — unsupported narrative text is never
   sent to the client. Dropped quotes and discarded narratives are logged in full to
   `auc/data/logs/summary_validation.log`.

Malformed JSON is retried once for that sub-competency alone, then marked
`generation_failed`; one bad section never takes down the report.

Model, timeout (600s per call), and options are configured at the top of
`summary_builder.py` (`SUMMARY_MODEL`, overridable with the `AUC_SUMMARY_MODEL`
environment variable, or per-run via the model dropdown in the UI). The summaries
are written by Ollama whichever retrieval engine is in use.

If the ontology or index is missing, or the engine's embedder is not running, the
stream emits an `error` event explaining what to fix. The older token-streaming
endpoint (`POST /api/residents/{id}/generate-summary`, NDJSON) is still present
and still uses `compose_prompt` for its single combined prompt.

## Setup / rebuild

`setup.sh` builds the index itself. By hand, from the repo root, using the
backend's Python environment:

```bash
# one-time: install the dependency, and the embedding model for Standard
auc/backend/venv/bin/pip install -r auc/backend/requirements-rag.txt   # chromadb, pinned
ollama pull qwen3-embedding:0.6b

# one-time, for NVIDIA Nemotron: start its two containers (a DGX Spark, or any
# machine with a capable NVIDIA GPU). The first run needs `docker login nvcr.io`
# with an NGC API key, and downloads several GB.
bash auc/start-nemotron.sh

# (re)build the index after editing the Markdown files — every engine this
# machine can run, or one with --engine ollama / --engine nemotron
auc/backend/venv/bin/python auc/rag/build_index.py

# then restart the app — it holds the index it opened at startup, so until you
# restart it keeps searching (and reporting on) the previous one
systemctl --user restart auc

# sanity-check retrieval
auc/backend/venv/bin/python auc/rag/test_query.py "missed a posterior circulation stroke"
auc/backend/venv/bin/python auc/rag/test_query.py --engine nemotron "missed a posterior circulation stroke"
```
